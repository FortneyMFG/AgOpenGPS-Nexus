# Nexus developer setup quick start

This guide walks you through the two fastest ways to get AgOpenGPS Nexus running on your workstation: downloading the packaged release zips or building from source. It captures the exact commands our CI uses so you can reproduce the environment locally.

## Prerequisites

- 64-bit Windows 10/11 or a recent Linux distribution (Ubuntu 22.04+ is validated in CI).
- [.NET 8 SDK](https://dotnet.microsoft.com/download) so the `dotnet` CLI is available. The source tree and helper scripts all assume the .NET 8 toolchain.【F:Nexus SourceCode/README.md†L41-L70】【F:tools/scripts/nexus.ps1†L11-L118】
- PowerShell 7+ (`pwsh`) for running the helper and packaging scripts. Windows ships with it by default; install it on Linux via your package manager.

## Option A — Use the packaged release downloads

Every tagged release runs the **Nexus Release Packaging** workflow, producing ready-to-run artifacts for Windows and Linux. Grab the assets that match your platform from the release page.

### Windows

1. Download `AgOpenGPS.Nexus-win-x64.zip` (or the single-file `AgOpenGPS.Nexus-win-x64.exe`) from the latest release. These files are published automatically when the release workflow completes.【F:.github/workflows/release.yml†L1-L71】
2. Extract the zip to a working folder (for example `C:\AgOpenGPS\Nexus`). The archive contains `AgOpenGPS.Nexus.exe`, `LICENSE.txt`, and a usage README generated by the packaging script.【F:tools/ci/package-windows.ps1†L55-L118】
3. Double-click `AgOpenGPS.Nexus.exe` to launch the Avalonia shell. If you prefer a Program Files install with a Start Menu shortcut, run the bundled `install.ps1` from an elevated PowerShell prompt.【F:tools/ci/package-windows.ps1†L55-L167】

### Linux

1. Download `AgOpenGPS.Nexus-linux-x64.zip` from the release assets.【F:.github/workflows/release.yml†L72-L110】
2. Extract the archive, which contains the self-contained `AgOpenGPS.Nexus` binary, `LICENSE.txt`, and a short README with usage instructions.【F:tools/ci/package-linux.ps1†L53-L109】
3. Ensure the executable bit is set (`chmod +x AgOpenGPS.Nexus`) and start the UI with `./AgOpenGPS.Nexus`. No system-wide install is required because the publish is self-contained.【F:tools/ci/package-linux.ps1†L65-L109】

## Option B — Build from source

1. Clone the repository and change into the checkout:
   ```bash
   git clone https://github.com/AgOpenGPS/AgOpenGPS-Nexus.git
   cd AgOpenGPS-Nexus
   ```
2. Restore dependencies and build the solution. This mirrors what CI does before packaging:
   ```bash
   dotnet restore "Nexus SourceCode/AgOpenGPS.Nexus.sln"
   dotnet build "Nexus SourceCode/AgOpenGPS.Nexus.sln" --configuration Release
   ```
   【F:Nexus SourceCode/README.md†L41-L70】
3. Launch whichever host you need using the helper script:
   - UI shell: `pwsh ./tools/scripts/nexus.ps1 run ui`
   - Core host (headless backend): `pwsh ./tools/scripts/nexus.ps1 run core`
   - AgIO bridge: `pwsh ./tools/scripts/nexus.ps1 run agio`
   - Composite simulation (headless smoke): `pwsh ./tools/scripts/nexus.ps1 sim`
   The script resolves the correct project paths and enforces that the .NET SDK is available before shelling out to `dotnet run`.【F:tools/scripts/nexus.ps1†L11-L118】

## After the first launch

- The UI persists connection settings to `%AppData%/AgOpenGPS/Nexus/connection-settings.json` on Windows or `$XDG_CONFIG_HOME/AgOpenGPS/Nexus/connection-settings.json` on Linux. Update the endpoint once and the shell reuses it on subsequent runs.【F:Nexus SourceCode/README.md†L70-L120】
- You can validate the deterministic simulation without hardware by pressing **Play** in the Simulation controls and adjusting the playback rate. This is the same workflow covered in the Windows no-hardware quick start.【F:docs/howto/windows-no-hw.md†L1-L76】

With these steps you can either download a release zip for instant UI access or reproduce the full CI build locally when you need to make code changes.
